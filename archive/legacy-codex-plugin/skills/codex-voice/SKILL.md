# Codex Voice

This plugin bundles registration hooks and guidance. A trusted `SessionStart` hook registers the current session on startup or resume; a `UserPromptSubmit` hook registers an already-open session at its next user prompt. Both invoke `CodexVoice.exe --register-from-hook`, which must read the exact `session_id` from the hook's JSON on standard input. The native Windows companion handles the global hotkey, microphone, local recognition, overlay, and Codex session delivery. Installing this plugin does not install that companion or trust its hooks.

1. Read this repository's `docs/status.md` and `plugins/codex-voice/README.md` before giving install instructions. The public repository currently has no companion installer or buildable companion source.
2. Automatic registration needs `CodexVoice.exe` on `PATH`, hooks enabled, and the user's trust for the current hook definition. The helper must read `session_id` from hook standard input and register idempotently; the prompt hook runs for every user prompt. Do not claim an already-open session was registered merely because the plugin was installed. If the companion is absent or the hooks are untrusted, explain why registration cannot run.
3. For an existing companion, use its `--binding-status` to diagnose whether this exact session is bound. The trusted hooks and `--register-from-hook` are the normal registration path. If the user explicitly requests a legacy manual binding diagnostic, locate the executable through `CODEX_VOICE_EXE` or an installed command and run only `--bind-session` in this session's tool shell. That diagnostic helper must read `CODEX_THREAD_ID` from its inherited environment; never pass a model-generated, title-derived or copied UUID as an argument. Treat a nonzero exit or missing environment value as an unbound session. Manual binding does not establish prompt delivery or identify the foreground Windows Terminal tab, so the overlay still requires visible recipient confirmation.
4. The hooks register session IDs only; they do not deliver prompts. The overlay shows microphone loading, ready and error states. Recognized text remains editable. Enter attempts immediate submission and closes only after Codex accepts it; the Send button keeps the overlay open. The quick hotkey uses push-to-talk and attempts direct submission on release. If the direct channel is unavailable, keep the text editable and say clearly that it was not sent. Do not offer `codex queue` as immediate delivery. Escape cancels. The message carries `[via Voice Connector]` as its source marker.
5. If delivery is rejected or its outcome is unknown, preserve the user's text and inspect the exact target before any retry. Keep audio, models, transcripts, private keys and local session databases on the user's PC. Do not claim that account login, phone access, Claude Code or other operating systems are currently available.
