# CLI

CLI is a separate developer product proposed for `cli.aiqoo.ru`. It shares only a parent domain with AIQOO. Its accounts, user database, API and device connections are independent of AIQOO Core and platform accounts.

The existing Windows Voice Connector works with visible Codex CLI tabs in CMD and PowerShell. It captures speech and runs Vosk/Whisper locally, shows editable text, and attempts delivery to the selected exact session with the `[via Voice Connector]` marker. The owner confirmed both short and long local messages reached the intended session after Enter closed the overlay. A buildable desktop source package is in `connector/windows`; no installer or binary has been released.

The public site uses a restrained developer-documentation style. It explains the current Windows prototype honestly, links to the GitHub project, and provides an independent CLI account. A separate private backend implements GitHub sign-in, a verified email stored in CLI's own database, revocable web sessions, and pending device pairing. Its HTTPS route and API were activated on NL on 2026-09-30. Completed real user login and an authenticated desktop/browser connection still need live verification. No paid tier is planned.

The web workspace lets an authenticated user link their PC, choose an available exact Codex session, and see three recent user/AI messages updating live. The desktop and browser encrypt these history snapshots with their paired key; the private server routes them without storing the conversation. The browser can record PCM audio, ask the PC to transcribe it locally, edit the returned text, and explicitly send literal text to the selected session, including code punctuation, line breaks and emoji. The PC must be unlocked and that session visible. A send is confirmed only after a matching entry appears in the exact Codex rollout; an uncertain result is never retried automatically. The private server neither transcribes audio nor runs Codex commands.

The owner requested a usable chat interface on 2026-09-30. The account workspace now separates the session list from the scrollable conversation and keeps the composer below it. User messages are distinct from replies. Enter sends, Shift+Enter inserts a line break, and profiles/device management remain accessible below the chat. The same workspace adapts to phone screens. Text length and terminal control-code bounds remain; ordinary quotes, shell-like punctuation and emoji are accepted.

The owner requires explicit local approval of device binding (2026-09-30): open the account from the desktop, click «Привязать» in that account, and approve the request with «ОК» on the exact PC. A browser claim remains pending until approval; closing the PC request, cancelling it, or missing its deadline cannot grant access. The existing QR flow uses the same approval. This is an additional approval of binding, not a new requirement to confirm each voice activation. Google login is also required; account-linking policy and a separate Google OAuth client remain pending owner input.

Voice activation must start a fresh empty recording immediately in the exact captured Codex session, without «Подтвердить сессию» (owner reiterated 2026-09-30). Older drafts, including uncertain sends and drafts addressed to another tab, are preserved locally and never restored or replayed automatically by the hotkey. A later fresh send cannot overwrite those preserved drafts. Exact session validation before sending remains automatic.

Product constraints: no silent queue, no automatic switch to a different session, and no claim of delivery until the selected Codex session provides a receipt. Existing user TUI sessions and drafts must not be reset. Claude Code, macOS and Linux are future adapters, not current support.

Owner packaging requirement (2026-10-01): the Windows Voice Connector needs a usable installer and a desktop shortcut on the owner's PC. The owner also asked for the built desktop installer to be present with the Git project, then chose a downloadable GitHub Release asset instead of Git LFS. Installer source stays in Git. This replaces the earlier source-only distribution state; it does not change session delivery, account boundaries, or the server. The owner's earlier question about selling the product has not yet specified a price or paid-tier policy.
